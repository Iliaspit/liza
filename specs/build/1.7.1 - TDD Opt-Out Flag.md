# 1.7.1 — TDD Opt-Out Flag

**Story**: Phase 1 — Config flag, submission gate, prompt conditioning

## Scope

### In Scope

- `Config.TDDEnabled *bool` field with `IsTDDEnabled()` helper (nil → true)
- `liza init --no-tdd` flag wiring through CLI → InitParams → state
- Submission gate guard: skip TDD check when `IsTDDEnabled()` returns false
- `TDDEnabled bool` threaded through coder, reviewer, code planner, code plan reviewer, and orchestrator prompt contexts
- Template conditionals for TDD-enabled vs TDD-disabled instructions
- Architecture spec updates (overview.md, roles.md, MULTI_AGENT_MODE.md)
- ADR-0044 documenting the decision
- Configuration documentation update

### Out of Scope

- OutputEntry inter-task dependencies (Phase 2 — story 1.7.2)
- Epic planner, US writer, US reviewer prompt changes (TDD is a coding concern)
- Migration tooling for existing workspaces (manual `state.yaml` edit suffices)

## Done When

- `IsTDDEnabled()` returns true for nil, true for explicit true, false for explicit false
- YAML round-trip preserves `tdd_enabled: false` and omits nil values
- `liza init --no-tdd "desc" --spec specs/vision.md` produces `state.yaml` with `tdd_enabled: false`
- `liza init "desc" --spec specs/vision.md` (no flag) produces `state.yaml` without `tdd_enabled` field
- Submission with TDD disabled + no test files succeeds
- Submission with TDD enabled (default) + no test files fails (existing behavior preserved)
- Coder prompt includes TDD instructions when enabled, implementation-focus instructions when disabled
- Reviewer prompt includes TDD quality gates when enabled, implementation-quality focus when disabled
- Code Planner prompt includes test task separation guidance when TDD is disabled
- Code Plan Reviewer prompt includes test task coverage check when TDD is disabled
- Orchestrator self-validation gate reflects TDD configuration
- `make test` passes
- `go vet ./...` passes

# 1.7.2 — OutputEntry Inter-Task Dependencies

**Story**: Phase 2 — Structured test task ordering via output entry dependencies

## Scope

### In Scope

- `OutputEntry.DependsOn []int` field (indices into sibling entries)
- Validation in `set_task_output.go`: bounds checking, self-reference prevention, cycle detection (DFS)
- `proceed.go` child task wiring: two-pass approach
  - First pass: generate all child task IDs (`{parentID}-{transitionName}-{index}`)
  - Second pass: create tasks with resolved `DependsOn` pointing to sibling task IDs
- MCP schema update: `liza_set_task_output` tool description and `extractOutputEntries` handler accept `depends_on` on output entries
- `server_registration.go` tool description update
- Code Plan Reviewer prompt: verify dependency correctness in output entries

### Out of Scope

- Cross-parent dependencies (dependencies between output entries from different planning tasks)
- Automatic test task generation (Code Planner creates these explicitly)

## Done When

- `OutputEntry.DependsOn` serializes to/from YAML correctly
- Setting `depends_on: [0]` on output entry 1 creates a task that depends on the task generated from entry 0
- Validation rejects: out-of-bounds indices, self-references, cycles
- MCP tool `liza_set_task_output` accepts `depends_on` field on output entries
- Code Plan Reviewer prompt includes dependency validation checklist item
- Existing output entries without `depends_on` continue to work unchanged

## Design Notes

```go
type OutputEntry struct {
    Desc      string `yaml:"desc"`
    DoneWhen  string `yaml:"done_when"`
    Scope     string `yaml:"scope"`
    SpecRef   string `yaml:"spec_ref"`
    DependsOn []int  `yaml:"depends_on,omitempty"`
}
```

### proceed.go Resolution

```
// First pass: generate IDs
childIDs := make([]string, len(entries))
for i, entry := range entries {
    childIDs[i] = fmt.Sprintf("%s-%s-%d", parentID, transitionName, i)
}

// Second pass: create tasks with resolved dependencies
for i, entry := range entries {
    var depends []string
    for _, depIdx := range entry.DependsOn {
        depends = append(depends, childIDs[depIdx])
    }
    createTask(childIDs[i], entry, depends)
}
```

### Cycle Detection

DFS-based with three-color marking (white/gray/black). Graph is small (typically <20 entries), so O(V+E) is fine.
